# T05 AUD 통화 추가 — A → B 인수인계

## 1. 목표와 범위
기존 USD/EUR/JPY/CNY/GBP에 AUD를 추가한다. 1 AUD당 KRW를 조회·저장·표시하고 KST 어제 대비 차이와 변화율을 계산한다. 기존 5개 통화와 실패 대응 기능을 보존한다. 과거 AUD가 없는 기록에 값을 만들거나 소급 채우지 않는다.

## 2. 시작 상태와 실행 환경
기준 커밋: 2e465aa318728c2d792ae8b85da8a4902f36b638
프로젝트: 과제/환율정보판. Vercel Root Directory도 이 경로다.
별도 npm 의존성 없이 CommonJS 서버리스 API와 브라우저 JS를 사용한다. HTML 파일 직접 열기로 서버 API를 검사할 수 없다. Vercel 배포 환경에서 실행하거나 Vercel CLI의 로컬 환경을 별도로 준비한다.
서버 환경변수 이름: SUPABASE_URL, SUPABASE_SECRET_KEY. 값은 저장소·문서·대화에 넣지 않는다.

## 3. A가 완료한 작업
index.html: AUD 카드와 aud-title/aud-rate/aud-change ID 추가. 값은 —, 상태는 연결 준비 중.
style.css: 데스크톱 통화 카드 5열을 3열로 바꿔 여섯 카드가 2행으로 배치되게 했다. 기존 미디어 쿼리는 유지했다.
board.js와 서버/DB는 수정하지 않았다. 실제로 조회 가능한 통화는 아직 5개이므로 제목도 5개로 유지했다.

## 4. B의 남은 작업과 변경 위치
api/_lib/exchange.js: CURRENCIES, UNITS, SELECT 컬럼, DB 행 직렬화/역직렬화, 검증에 AUD 연결.
board.js: 통화 목록/단위, 화면/이력/계산 근거, 합성 응답과 검사에 AUD 연결. 과거 AUD 없는 행을 정상적으로 읽고 비교 불가 표시.
index.html: 완성 후 제목/설명을 6개로 변경, 이력 표 AUD 열과 colspan 반영, 준비 중 문구 제거.
DB 마이그레이션 SQL을 파일로 제공: aud_krw는 과거 행을 위해 NULL 허용, 값이 있으면 양수. 적용은 사용자가 Supabase에서 수행. 기존 행·RLS·권한 유지.
주의: 현재 검증은 통화별 raw/sourceDates/rates가 모두 있는지 검사하므로 목록만 늘리면 과거 행을 거부할 수 있다. 누락과 손상값을 구분한다. 현재 합성 검사는 브라우저 처리 검사이며 서버 API/DB 실패 검사를 대신하지 않는다.

## 5. 공통 검사와 결과
CHECKS.md의 검사 10개를 A/B 동일하게 사용한다. 검사를 바꾸지 말고 결과와 증거를 각각 기록한다.
사전 초안에서만 소스 구조 검사와 JS 구문 검사 실행. 정식 A 실행 결과는 A-RESULTS.md를 확인할 것. 브라우저/실제 API/DB 검사는 미실행. AUD 전체 기능은 미완료.
B는 성공했다고 추정하지 말고 실제 실행 결과와 미실행 항목을 분리한다.

## 6. 공통 사용 상한과 측정
PLAN.md 기준: A/B 각각 경과 시간 60분, 사용자 작업 요청 최대 10회. 내부 도구 호출은 별도로 기록한다.
현재 코드 변경은 기준 확정 전 사전 초안이다. 정식 A 시작·종료·인계 기록은 아직 미등록이다. 사전 고정 이후 실행처럼 보고하지 않는다.
측정표에는 세션 X/Y로 표시하며 실제 시간·횟수·검사 결과만 기록한다. 누락된 측정은 미기록으로 남긴다.

## 7. 재개 방법과 인계 조건
A 변경을 저장·커밋한 뒤 해당 전체 SHA를 B에게 전달한다. B는 이전 대화 없이 이 저장소와 문서만 읽는다.
먼저 목표/현재 상태/남은 작업/실행 방법을 자기 말로 요약한 후 구현한다. 막힌 점과 사용자에게 추가로 받은 정보도 기록한다.
완료 시 검사 결과, 변경 파일, DB 적용 방법, 한계, 완료 전체 SHA를 문서에 남긴다. 공개 비교 보고서는 실제 두 세션 결과가 모인 뒤 작성한다.
