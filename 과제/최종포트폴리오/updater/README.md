# 편승훈 포트폴리오 기록 갱신 장치

리추얼·출석·과제 제출 기록에서 공개 사이트에 사용할
숫자와 날짜·근거가 붙은 문단 후보를 만듭니다.

외부 AI API와 추가 라이브러리는 사용하지 않습니다.
검토 전 후보를 사이트에 자동으로 반영하지 않습니다.

## 실행 환경

- Python 3.10 이상
- 추가 패키지 설치 불필요
- 인터넷 연결 불필요

## 폴더 구성

```text
updater/
├ README.md
├ update.py
├ input/
│  ├ rituals.json
│  ├ attendance.json
│  └ tasks.json
└ output/
   ├ metrics.json
   ├ candidates.json
   └ result.md
```

## 실행 방법 3단계

### 1. 입력 준비

input 폴더에 JSON 파일 3개를 넣습니다.

- rituals.json: 날짜별 아침·마무리 리추얼
- attendance.json: 출석 화면의 집계·조회일·출처
- tasks.json: 과제별 제출일·승인 상태·확인 근거

공개하거나 제출할 입력 파일은 다른 사람의 실명·연락처와
비밀값을 제거한 자료여야 합니다.

### 2. 실행

압축을 푼 updater 폴더에서 실행합니다.

```powershell
python .\update.py
```

### 3. 결과 검토

output/result.md에서 집계와 출처를 확인합니다.
output/candidates.json에서 후보 문장과 원문 근거를 대조합니다.

직접 검토한 숫자와 선택한 문단만
사이트의 data/approved.json에 반영합니다.

## 입력과 계산 규칙

### 리추얼

- 날짜는 원자료의 KST 날짜를 사용합니다.
- 아침 또는 마무리 내용이 있는 고유 날짜를 셉니다.
- 마무리가 없는 날짜를 미실천으로 계산하지 않습니다.
- 같은 날짜가 중복되면 중단합니다.
- 강점 행동 응답은 실천·일부 실천·미실천으로 분류합니다.
- 알 수 없는 응답은 임의로 분류하지 않고 중단합니다.

실천 또는 일부 실천 비율:

```text
(실천 건수 + 일부 실천 건수) ÷ 마무리 기록 수 × 100
```

이 값은 본인의 자기보고이며 출석률이나 과제 완료율이 아닙니다.
마무리 기록이 없으면 비율을 계산하지 않습니다.

### 출석

출석 화면에서 확인한 집계와 조회일을 사용합니다.
출석률은 원천 화면의 표시값을 유지하며 재계산하지 않습니다.
미확정 날짜는 확정된 출석으로 바꾸지 않습니다.

### 과제 제출과 승인

과제 ID별 제출 기록을 셉니다.
중복 ID는 거부합니다.

제출 시각의 출처는 과제별 제출 기록 MD입니다.
승인 상태는 본인이 확인하여 입력한 값입니다.
승인 시각·채점 점수·작업 시간은 추정하지 않습니다.

입력에 없는 과제는 실패나 미제출로 판단하지 않습니다.

## 문단 후보 규칙

마무리의 「강점을 위해 노력하고 생각한 것」에서
고정 키워드로 장면을 찾습니다.

- 자기조절력
- 대인관계력
- 자기동기력

능력별 최신 날짜부터 최대 5건을 선택합니다.
같은 장면이 여러 능력의 후보가 될 수 있습니다.
후보가 없으면 만들어 채우지 않습니다.

각 후보에는 날짜·원문·근거 위치·일치 키워드가 포함됩니다.
키워드 일치는 능력이 입증되었다는 판정이 아닙니다.

## 승인과 사이트 반영

모든 출력과 문단 후보는 approved가 false입니다.
update.py는 사이트의 approved.json을 수정하지 않습니다.

1. 후보 문장과 원문을 대조합니다.
2. 사실·개인정보를 확인하고 공개할 문장을 선택합니다.
3. 승인한 내용만 approved.json에 옮깁니다.

metrics.json에서는 다음 항목을 사용합니다.

- metrics
- attendance
- tasks

candidates.json에서는 선택한 paragraphs 항목을 사용합니다.

승인한 공개 파일과 문단의 approved를 true로 설정합니다.
기존 논문·문서·연락 링크는 유지합니다.

approved 표시는 사람의 검토 절차를 나타내며,
접근 제어나 로그인 기능은 아닙니다.

## 현재 기준 자료의 예상 결과

기준일: 2026-10-15 KST

```text
기록 41일 / 아침 41건 / 마무리 40건
실천 25건 / 일부 실천 13건 / 미실천 2건

출석 40일 / 결석 2일 / 미확정 1일
화면 표시 출석률 93%

제출 11건 / 승인 11건 / 승인 상태 미확인 0건

문단 후보 13건
```

입력이 바뀌면 결과도 바뀔 수 있습니다.
개인정보 검토로 원문을 수정하면 후보 수가 달라질 수도 있습니다.

## 동일 결과 검사

```powershell
python .\update.py --output .\check-a
python .\update.py --output .\check-b

foreach ($name in @("metrics.json", "candidates.json", "result.md")) {
    $hashA = (Get-FileHash ".\check-a\$name" -Algorithm SHA256).Hash
    $hashB = (Get-FileHash ".\check-b\$name" -Algorithm SHA256).Hash

    Write-Host "$name 동일 결과: $($hashA -eq $hashB)"
}
```

2026-10-15에 사용자가 실행해 확인한 결과:

```text
metrics.json 동일 결과: True
candidates.json 동일 결과: True
result.md 동일 결과: True
```

출력에는 실행 시각·절대 경로·난수를 넣지 않습니다.
입력 파일 3개의 SHA-256을 결과에 남깁니다.

같은 입력은 같은 바이트의 파일을 뜻합니다.
JSON 공백만 수정해도 입력 해시는 달라집니다.

## 새 폴더 재현 검사

새 폴더에 다음을 복사합니다.

- update.py
- README.md
- input 폴더와 JSON 파일 3개

기존 output 폴더는 복사하지 않습니다.
새 폴더에서 「실행 방법 3단계」를 따라 실행하고,
집계와 결과 파일 3개가 생성되는지 확인합니다.

소스나 입력이 바뀌면 동일 결과 검사와 새 폴더 검사를 다시 합니다.

## 개인정보 확인

자동 검사는 일부 이메일·전화번호·주민등록번호·비밀키·토큰
형태를 찾아 해당 원문을 문단 후보에서 제외합니다.

일반적인 사람 이름과 별명까지 모두 찾지는 못합니다.
「개인정보 형태 0건」은 개인정보가 없다는 보장이 아닙니다.

공개 저장소와 제출 ZIP에 넣기 전에 입력·출력을 직접 읽고
본인 외의 실명·연락처와 비밀값을 제거합니다.

입력을 수정한 뒤에는 다시 실행해 마지막 결과를 갱신합니다.
가리지 않은 원본은 공개 폴더 밖에 보관합니다.

## 오류와 한계

- JSON 형식·날짜·집계가 잘못되면 안내 후 중단합니다.
- 파일 누락 시 input 폴더와 파일명을 확인합니다.
- 실행 실패 후 이전 출력이 남을 수 있으므로 성공 여부를 확인합니다.
- 문단 후보는 고정 키워드 방식이어서 문맥을 오해할 수 있습니다.
- 리추얼의 실천 여부는 자기보고입니다.
- 출석·제출 서버에 실시간으로 접속하지 않습니다.
- 후보를 공개하려면 사람의 검토와 승인이 필요합니다.
